# Security policy

## Reporting a vulnerability

Do not open a public issue. On a public repository, report it privately
through **Security > Report a vulnerability**. If the repository does not
show that option (private repositories), contact the maintainer privately
through the details on the owner's GitHub profile.

Include what you found, how to reproduce it, and the affected version or
commit.

## What happens next

1. You get an answer within 7 days that confirms the report and says
   whether it is in scope.
2. The fix is developed privately. You hear about progress at least every
   14 days until it ships.
3. The fix is released, and its release notes (and, on a public
   repository, a security advisory) name the affected versions. You are
   credited unless you ask not to be.

## Scope

In scope: the code, workflows and published packages of this repository.
Out of scope: vulnerabilities in dependencies that are already reported
upstream, and findings that need an already compromised machine or account.

## Supported versions

Only the latest release receives security fixes.
